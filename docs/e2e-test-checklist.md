# E2E テストチェックリスト

Browser Toolkit を Chrome 拡張機能として実ブラウザで手動確認する際のチェックリストです。自動 E2E テスト（`pnpm run test:e2e`）で網羅していない経路や、実サイトでの挙動を確かめる際に使います。

## 事前準備

### 1. 拡張機能のビルド

```bash
pnpm run build
```

### 2. Chrome 拡張機能として読み込み

1. Chrome で `chrome://extensions/` を開きます。
2. 右上の「デベロッパーモード」を有効にします。
3. 「パッケージ化されていない拡張機能を読み込む」をクリックします。
4. `manifest.json` がある `browser-toolkit/` のルートディレクトリを選択します。

### 3. 初期設定

1. 拡張機能アイコンをクリックしてポップアップを開き、サイドバー下部の「設定」からオプションページを開きます。
2. AI プロバイダーを設定します。
   - API キー系（OpenAI / Anthropic / z.ai）: 有効なトークンを入力して保存し、「トークン確認」が成功することを確認します。
   - ChatGPT プラン: 「ChatGPT で続行」でサインインを完了し、「接続テスト」が成功することを確認します。
3. 対応するモデルを選択します。

## テストケース

### 1. テーブルソート・フォーカス維持（サイト別機能）

#### 1.1 手動ボタンによるテーブルソート

- [ ] 準備: テーブルを含むページ（例: [HTML Table Generator](https://www.tablesgenerator.com/html_tables) で作成した 3 列×5 行のテーブル）を開く
- [ ] ポップアップを開き、「サイト別機能」タブへ移動する
- [ ] 「このタブで有効化」ボタンをクリックする
- [ ] 期待: テーブルの `<th>` ヘッダーに「⇅」が表示される
- [ ] 各列のヘッダーをクリックする
- [ ] 期待: クリックするたびに昇順（↑）・降順（↓）が切り替わり、数値列・テキスト列が意図どおりにソートされる

#### 1.2 自動ソート（URL パターンマッチ）と行フィルタリング

- [ ] ポップアップの「サイト別機能」タブの「自動ソート対象サイト」でパターン（例: `*wikipedia.org*`）を追加する
- [ ] 一致するテーブル付きページを開く
- [ ] 期待: ページ読み込み時に自動でソートが有効化される（再読み込み後も同じ）
- [ ] パターンの行フィルタリングを ON にし、0円・ハイフン・空白・N/A の行が非表示になることを確認する

#### 1.3 動的テーブルの検出

- [ ] 初期状態ではテーブルを持たないページを開く
- [ ] JavaScript で動的にテーブルを挿入する
- [ ] 期待: `MutationObserver` が追加を検出し、自動でソートが有効化される

#### 1.4 フォーカス維持

- [ ] ポップアップの「サイト別機能」タブの「フォーカス維持」にテスト対象ページの URL パターンを追加する
- [ ] 「現在のタブ診断」のステータス表示を確認し、必要なら「このタブを再読み込み」を実行する
- [ ] 期待: 診断結果が「有効」になり、別タブへ切り替えても対象ページの `document.visibilityState` が表示中として扱われる

---

### 2. Context Actions・カレンダー登録・Gemini で要約

#### 2.1 テキスト要約（オーバーレイ表示・フォローアップ質問）

- [ ] Web ページ上でテキストを選択する（200 文字以上を推奨）
- [ ] 右クリック →「Browser Toolkit」→「要約」を選ぶ
- [ ] 期待: オーバーレイ UI が開き、要約結果・ソース情報・コピーボタンが表示される
- [ ] オーバーレイのピン留め、Markdown / シンプル表示切り替え、フォローアップ質問の送信が動作することを確認する

#### 2.2 カスタムアクション

- [ ] ポップアップの「アクション」タブを開き、「アクション編集」で「新規作成」を選ぶ
- [ ] タイトルとプロンプト（例: `次のテキストを箇条書きで英語に翻訳してください: {{text}}`）を入力して「保存」する
- [ ] ページ上でテキストを選択し、右クリック →「Browser Toolkit」→ 作成したアクションを実行する
- [ ] 期待: 実行結果がオーバーレイに表示される

#### 2.3 カレンダー登録

- [ ] イベント情報を含むテキストを選択する
  ```
  打ち合わせ
  日時: 2026年12月15日 14:00〜16:00
  場所: 会議室A
  ```
- [ ] 右クリック →「Browser Toolkit」→「カレンダー登録」（またはポップアップ →「カレンダー」タブ →「抽出する」）を実行する
- [ ] 期待: タイトル・日時・場所・概要が抽出される
- [ ] 「Googleカレンダーに登録」をクリックし、Google カレンダーの新規イベント作成画面が開くことを確認する（`.ics` ダウンロードも確認）

#### 2.4 Gemini で要約

- [ ] Web ページ上でテキストを選択し、右クリック →「Browser Toolkit」→「Geminiで要約」を選ぶ
- [ ] 期待: `https://gemini.google.com/app` が新しいタブで開き、調査用プロンプトが自動入力・送信される（未ログイン等で失敗した場合はクリップボードへコピーされる通知が出る）

---

### 3. テキストテンプレート

#### 3.1 テンプレート管理

- [ ] オプションページ →「テンプレート」タブを開く
- [ ] 「新規追加」でタイトル（例: `Thanks`）と内容（例: `Thank you for your help!`）を入力して保存する
- [ ] 作成したテンプレートが一覧に表示され、ドラッグ&ドロップで並び替えや非表示切り替えができることを確認する

#### 3.2 テンプレート挿入

- [ ] 入力可能なフィールド（例: GitHub Issue、Gmail）にフォーカスを合わせる
- [ ] 右クリック →「Browser Toolkit」→「テンプレートを貼り付け」→「Thanks」を選ぶ
- [ ] 期待: テンプレートの内容がプレーンテキストとして入力欄に挿入される

---

### 4. リンク作成・QR コード生成

#### 4.1 タイトルと URL のコピー

- [ ] ポップアップを開き、「リンク作成」タブへ移動する
- [ ] 期待: 現在のタブのタイトル・URL・プレビュー・QR コードが表示される
- [ ] 各形式を選択して「コピー」をクリックし、クリップボードの内容を確認する
  - [ ] URL
  - [ ] テキスト（タイトル + URL）
  - [ ] Markdown: `[タイトル](<URL>)`
  - [ ] GitHub（#番号 + タイトル）: GitHub の PR / Issue ページで `[#123 タイトル](<URL>)` 形式になる
  - [ ] HTML `<a>`
  - [ ] Org-mode
  - [ ] BBCode

#### 4.2 右クリックメニューからのコピーと QR コード表示

- [ ] ページ内で右クリック →「Browser Toolkit」→「タイトルとリンクをコピー」→ 任意の形式を選ぶ
- [ ] 期待: 選んだ形式でクリップボードにコピーされる
- [ ] 右クリック →「Browser Toolkit」→「QRコードを表示」を選び、ページ上に QR コードのオーバーレイが開き Escape で閉じられることを確認する

---

### 5. 検索エンジン・まとめて検索

#### 5.1 検索エンジンとグループの管理

- [ ] オプションページ →「検索エンジン」タブで既定のエンジン一覧が表示され、追加・ON/OFF・並び替えができることを確認する
- [ ] オプションページ →「まとめて検索」タブで既定の 3 グループ（「日用品系」「徹底比較」「トレンド」）が表示されることを確認する
- [ ] 新規グループ（例: `Tech`、Google・GitHub を選択）を追加して保存する

#### 5.2 検索と一括検索

- [ ] テキストを選択する（例: `React Hooks`）
- [ ] 右クリック →「Browser Toolkit」→「検索」→ 任意のエンジンを選び、検索結果タブが開くことを確認する
- [ ] 右クリック →「Browser Toolkit」→「まとめて検索」→「Tech」を選び、グループ内の各検索結果が新しいタブで開くことを確認する

---

### 6. エラーハンドリング

#### 6.1 無効な API トークン

- [ ] オプションページ →「設定」で無効なトークンを入力し、「トークン確認」をクリックする
- [ ] 期待: エラーメッセージが表示される

#### 6.2 テキスト未選択・空ページ

- [ ] 本文のないページなどでテキストを選択せずに右クリック →「Browser Toolkit」→「要約」を実行する
- [ ] 期待: 適切なエラー通知が表示される

#### 6.3 ネットワークエラー

- [ ] DevTools や OS 設定でオフライン状態にして Context Action を実行する
- [ ] 期待: ネットワークエラーを示すメッセージが表示される

---

### 7. テーマ切り替え

- [ ] オプションページ →「設定」でテーマ（自動 / ライト / ダーク）を切り替える
- [ ] 期待: ポップアップ・オプションページの見た目が即時切り替わる
- [ ] ページ上のオーバーレイを開き、選択したテーマが反映されること、またオーバーレイ上のテーマ切り替えボタンで自動・ライト・ダークが循環することを確認する

---

### 8. パフォーマンス

- [ ] 大規模テーブル: 100 行以上のテーブルでテーブルソートを有効化し、1 秒以内にヘッダー付与とソートが完了することを確認する
- [ ] 長文の要約: 20,000 文字を超えるテキストで要約を実行し、上限で切り詰められて `(以下略)` が付与されたうえで応答が返ることを確認する

---

### 9. 検索結果ブロックリスト

#### 9.1 ブロック追加と即時非表示

- [ ] Google で任意のキーワードを検索する
- [ ] 検索結果カードにカーソルを合わせ、遮断アイコンをクリックしてルールを追加する
- [ ] 期待: 対象の検索結果が即座に非表示になる

#### 9.2 件数バーの表示切り替え

- [ ] 非表示件数バーに件数が表示されることを確認する
- [ ] 「表示」/「非表示にする」を切り替え、非表示にした結果を一時的に再表示できることを確認する

#### 9.3 解除と再読み込み後の維持

- [ ] 対象カードからダイアログを開き「解除する」をクリックしたとき、**再読み込みなしで**その場に再表示されることを確認する
- [ ] 再読み込み後も追加・解除の状態が維持されることを確認する

#### 9.4 追加読み込みとポップアップからの管理

- [ ] ページ下部までスクロールして追加読み込みされた検索結果にも既存ルールが適用されることを確認する
- [ ] ポップアップ →「検索ブロック」タブで既存ルールの編集・削除を行い、検索結果ページの表示へ即座に反映されることを確認する

---

### 10. X の画像ズーム

- [ ] `x.com` で画像付きポストの写真表示（`/status/<id>/photo/<n>`）を開く
- [ ] 画像をクリックする
- [ ] 期待: Shadow DOM の全画面画像ビューアが開き、ズーム操作と Escape / 閉じるボタンでの終了が動作する
- [ ] 「元画像をダウンロード」をクリックし、元画像ファイルが保存されることを確認する

## バグ報告時の記録項目

テスト中に問題を見つけた場合は、以下の情報を添えて GitHub Issue に記録します。

- 環境: OS、Chrome バージョン、拡張機能バージョン（`manifest.json` の `"version"`）
- 再現手順: 1, 2, 3...
- 期待される動作 / 実際の動作
- エラー情報: DevTools の Console / Network タブのメッセージやスクリーンショット

## 完了確認

該当するテストケースを確認し終えたら手動 E2E テスト完了です。必要に応じて確認結果を PR や Issue に記録してください。

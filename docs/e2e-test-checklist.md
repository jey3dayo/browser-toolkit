# E2E テストチェックリスト

Browser Toolkit を Chrome 拡張機能として手動 E2E テストする際の確認項目をまとめています。

## 事前準備

### 1. 拡張機能のビルド

```bash
pnpm run build
```

### 2. Chrome 拡張機能として読み込み

1. Chrome で `chrome://extensions/` を開きます。
2. 「デベロッパーモード」を有効にします。
3. 「パッケージ化されていない拡張機能を読み込む」をクリックします。
4. `browser-toolkit` のルートディレクトリを選択します。

### 3. 初期設定

1. 拡張機能アイコンをクリックしてポップアップを開きます。
2. 「設定」を開きます。
3. AI プロバイダーを設定します。
   - プロバイダー: OpenAI / Anthropic / z.ai から選択
   - API トークン: 有効なトークンを入力
   - モデル: 対応するモデルを選択
4. 「トークンをテスト」ボタンをクリックし、接続が成功することを確認します。

## テストケース

### 1. テーブルソート機能

#### 1.1 手動ボタンによるソート

- [ ] **準備**: [HTML Table Generator](https://www.tablesgenerator.com/html_tables) で 3 列×5 行のテーブルを作成し、ページ上に表示する
- [ ] ポップアップを開き、「サイト別機能」タブへ移動する
- [ ] 「このページでテーブルソート機能を有効化」ボタンをクリックする
- [ ] **期待**: テーブルのヘッダーに「⬍」ボタンが追加される
- [ ] 各列のヘッダーボタンをクリックする
- [ ] **期待**: クリックするたびに昇順・降順が切り替わる
- [ ] 数値列・テキスト列・日付列それぞれで意図どおりにソートされることを確認する

#### 1.2 自動ソート（URL パターンマッチ）

- [ ] ポップアップの「サイト別機能」タブで「パターンを追加」を選ぶ
- [ ] パターンに `*table*`（ワイルドカード）を入力して「保存」をクリックする
- [ ] テーブルを含むページ（例: Wikipedia）を開く
- [ ] **期待**: ページ読み込み時に自動でソートボタンが追加される
- [ ] ページを再読み込みしても同じ動作になることを確認する

#### 1.3 動的テーブルの検出

- [ ] 初期状態ではテーブルを持たないページを開く
- [ ] JavaScript で動的にテーブルを挿入する
- [ ] **期待**: `MutationObserver` がテーブル追加を検出し、自動でソートボタンが付与される

---

### 2. Context Actions

#### 2.1 テキスト要約

- [ ] Web ページ上でテキストを選択する（200 文字以上を推奨）
- [ ] 右クリック →「Context Actions」→「要約」を選ぶ
- [ ] **期待**: オーバーレイ UI が開き、要約結果が表示される
- [ ] オーバーレイに以下の要素が含まれていることを確認する
  - [ ] 要約テキスト（箇条書き形式）
  - [ ] ソース情報（ページタイトル、URL）
  - [ ] クリップボードにコピーするボタン

#### 2.2 カスタムアクション

- [ ] ポップアップを開き、「Context Actions」タブへ移動する
- [ ] 「新規アクション」をクリックする
- [ ] 以下を入力して「保存」をクリックする
  - [ ] タイトル: `日本語に翻訳`
  - [ ] プロンプト: `次のテキストを日本語に翻訳してください: {{text}}`
- [ ] 英語テキストを選択し、右クリック →「日本語に翻訳」を実行する
- [ ] **期待**: 翻訳結果がオーバーレイに表示される

#### 2.3 カレンダーイベント抽出

- [ ] イベント情報を含むテキストを選択する
  ```
  打ち合わせ
  日時: 2026年2月15日 14:00〜16:00
  場所: 会議室A
  ```
- [ ] 右クリック →「Context Actions」→「カレンダーイベント抽出」を選ぶ
- [ ] **期待**: 抽出されたイベント情報が表示される
- [ ] 「Googleカレンダーに追加」ボタンをクリックする
- [ ] **期待**: Google カレンダーの新規イベント作成画面が開く

---

### 3. テキストテンプレート

#### 3.1 テンプレート管理

- [ ] テンプレート管理画面を開く
- [ ] 「新規テンプレート」をクリックする
- [ ] 以下を入力して「保存」をクリックする
  - [ ] タイトル: `Thanks`
  - [ ] 内容: `Thank you for your help!`
- [ ] 作成したテンプレートが一覧に表示されることを確認する

#### 3.2 テンプレート挿入

- [ ] 入力可能なフィールド（例: GitHub Issue、Gmail）にフォーカスを合わせる
- [ ] 右クリック →「テキストテンプレート」→「Thanks」を選ぶ
- [ ] **期待**: テンプレートの内容が入力欄に挿入される

---

### 4. リンクコピー機能

#### 4.1 タイトルと URL のコピー

- [ ] ポップアップを開き、「リンクコピー」タブへ移動する
- [ ] **期待**: 現在のタブのタイトルと URL が表示される
- [ ] 各フォーマットを選択して「コピー」ボタンをクリックする
  - [ ] Markdown: `[タイトル](URL)`
  - [ ] Plain: `タイトル URL`
  - [ ] タイトルのみ
  - [ ] URL のみ
- [ ] **期待**: 選択した形式でクリップボードにコピーされ、テキストエディタへ正しく貼り付けられる

#### 4.2 右クリックメニューからのコピー

- [ ] ページ内で右クリック →「タイトル＋URLをコピー」を選ぶ
- [ ] **期待**: Markdown 形式でクリップボードにコピーされ、テキストエディタへ正しく貼り付けられる

---

### 5. 検索エンジングループ

#### 5.1 グループ管理

- [ ] 検索エンジングループの管理画面を開く
- [ ] 既定のグループ（「お買い物」「トレンド」）が表示されることを確認する
- [ ] 「新規グループ」をクリックし、以下を入力して「保存」する
  - [ ] グループ名: `Tech`
  - [ ] 検索エンジン: Google、GitHub、Stack Overflow を選択

#### 5.2 グループ一括検索

- [ ] テキストを選択する（例: `React Hooks`）
- [ ] 右クリック →「検索エンジングループ」→「Tech」を選ぶ
- [ ] **期待**: Google、GitHub、Stack Overflow の検索結果がそれぞれ新しいタブで開く

---

### 6. エラーハンドリング

#### 6.1 無効な API トークン

- [ ] 設定画面で無効なトークンを入力する
- [ ] 「トークンをテスト」をクリックする
- [ ] **期待**: エラーメッセージが表示される（例: `Incorrect API key provided`）

#### 6.2 テキスト未選択

- [ ] テキストを選択せずに右クリック →「要約」を実行する（本文のないページなどで確認）
- [ ] **期待**: 適切なエラー通知が表示される（例: `要約対象のテキストが見つかりませんでした`）

#### 6.3 ネットワークエラー

- [ ] ネットワークをオフライン状態にする
- [ ] Context Action を実行する
- [ ] **期待**: ネットワークエラーを示すメッセージが表示される

---

### 7. テーマ切り替え

#### 7.1 ライト・ダークテーマ

- [ ] ポップアップを開く
- [ ] テーマ切り替え操作（🌙 / ☀️ または設定画面のテーマ選択）を行う
- [ ] **期待**: ライト・ダーク・システム設定の順にテーマが切り替わる
- [ ] オーバーレイ UI にも選択したテーマが反映されることを確認する

---

### 8. パフォーマンス

#### 8.1 大規模テーブルの処理

- [ ] 100 行以上のテーブルを含むページを開く
- [ ] テーブルソート機能を有効化する
- [ ] **期待**: 1 秒以内にソートボタンが追加され、ソート処理も 1 秒以内に完了する

#### 8.2 長文の要約

- [ ] 5,000 文字以上の長文を選択して要約を実行する
- [ ] **期待**: 20,000 文字の上限で切り詰められ「(以下略)」が付与される（上限超過時）
- [ ] 要約結果が 30 秒以内に表示される

---

### 9. 検索結果ブロックリスト

#### 9.1 ブロック追加で検索結果が非表示になる

- [ ] Google で任意のキーワードを検索する
- [ ] 検索結果カードにカーソルを合わせ、遮断アイコンをクリックする
- [ ] ダイアログからルールを追加する
- [ ] **期待**: 対象の検索結果が即座に非表示になる

#### 9.2 件数バーの表示切り替え

- [ ] 9.1 の直後に、ページ上部（または結果一覧付近）の非表示件数バーを確認する
- [ ] **期待**: 非表示になっている件数が表示される
- [ ] バーの表示トグルを切り替え、非表示にした結果を一時的に再表示できることを確認する

#### 9.3 解除が再読み込みなしで即時反映される

- [ ] 9.1 で追加したルールの対象カードにカーソルを合わせ、遮断アイコンをクリックする
- [ ] ダイアログで「解除する」をクリックする
- [ ] **ページを再読み込みせず**、その場で結果カードの表示を確認する
- [ ] **期待**: 再読み込みしなくても、解除した検索結果がその場で再表示される

#### 9.4 解除状態が再読み込み後も維持される

- [ ] 9.3 の操作後にページを再読み込みする
- [ ] **期待**: 再読み込み後も解除状態が維持され、対象の結果が表示されたままになる

#### 9.5 追加したルールが再読み込み後も残る

- [ ] ブロックルールを追加した状態でページを再読み込みする
- [ ] **期待**: 再読み込み後も同じルールが適用され、対象の結果が非表示になる

#### 9.6 スクロールで追加読み込みされた結果への適用

- [ ] ブロック対象サイトを含むキーワードで検索する
- [ ] ページ下部までスクロールし、追加の検索結果を読み込む
- [ ] **期待**: 追加読み込みされた結果にも既存ルールが適用され、対象が非表示になる

#### 9.7 ポップアップからのルール編集・削除

- [ ] ポップアップ → **検索ブロックリスト** タブを開く
- [ ] 既存ルールのパターンを編集する
- [ ] 既存ルールを削除する
- [ ] **期待**: 編集・削除の内容が検索結果ページの表示へ即座に反映される

## バグ報告時の記録項目

テスト中に問題を見つけた場合は、以下の情報を添えて GitHub Issue に記録します。

- **環境**
  - OS（例: macOS 14.0、Windows 11）
  - Chrome バージョン（例: 121.0.6167.85）
  - 拡張機能バージョン（`manifest.json` の `"version"`）
- **再現手順**
  1. ...
  2. ...
  3. ...
- **期待される動作**: ...
- **実際の動作**: ...
- **エラー情報**: DevTools の Console / Network タブのメッセージやスクリーンショット

## 完了確認

すべてのテストケースを確認し終えたら、手動 E2E テスト完了とします。必要に応じて確認結果を PR や Issue に記録してください。
